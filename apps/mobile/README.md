# @soundscape/mobile

Expo SDK 54 (React Native 0.81) app that mirrors the Soundscape Mixer on iOS and Android, using the same sounds, presets and share links as the web app.

## Environment

All optional; set them in your shell or an `.env` file before starting Expo:

```
EXPO_PUBLIC_ENV=development
# Web app origin used in share links. Defaults to the production web app.
EXPO_PUBLIC_APP_URL=https://soundscape-web-one.vercel.app
# Only needed if a sound has a recorded `file`.
EXPO_PUBLIC_ASSET_URL=https://cdn.example.com
```

## Commands

```bash
npm run start --workspace @soundscape/mobile      # Expo dev server
npm run ios --workspace @soundscape/mobile        # build and run on iOS
npm run android --workspace @soundscape/mobile    # build and run on Android
npm run typecheck --workspace @soundscape/mobile
npm run lint --workspace @soundscape/mobile
```

The app uses native modules (`expo-audio`, `expo-file-system`, `expo-web-browser`, `expo-secure-store`, `expo-document-picker`, `expo-crypto`), so use a development build (`expo run:*`) rather than Expo Go.

`ios/` and `android/` are generated by `expo prebuild` from `app.config.ts` and are not committed. Native changes go in the config or in `plugins/` (for example `with-pod-resource-deployment-target.js`, which Xcode 27 needs).

## How it works

- Each sound is synthesized the first time it is switched on and cached as a WAV file in the app's cache directory (`src/sound-files.ts`); later plays start instantly.
- `src/audio-engine.ts` keeps one looping `expo-audio` player per active sound. Player properties are set synchronously, so fast slider moves can't race each other, and the master volume scales every layer.
- Playback continues with the screen locked or another app in front (`UIBackgroundModes: audio` on iOS; on Android one layer runs the media playback service). Pausing or resuming from the lock screen or headphones pauses or resumes the whole mix. A looping player reports "paused" for a moment each time it wraps around, so an outside change only counts once it is still there 600 ms later.
- The mix is saved to AsyncStorage (debounced); playback always starts stopped.
- Share builds a self-contained web link and opens the native share sheet.

## Your sounds (accounts)

- **Sign in** (`src/account/auth.ts`) opens the website's sign-in pages in an ephemeral sign-in browser (`expo-web-browser`): Neon Auth's OAuth provider, authorization code with PKCE. The website hands the code back on `soundscape://auth/callback`; the app exchanges it for an access token (1 hour) and a refresh token (30 days, rotated on each use), kept in the Keychain/Keystore (`expo-secure-store`). The issuer, client ID and API identifier are in `src/account/config.ts`; the server side is described in `apps/web/README.md` ("Signing in from the native app").
- **The API** (`src/account/api.ts`) is the website's `/api/sounds/*`, called with `Authorization: Bearer`. A 401 refreshes once and retries; a refresh token that's no longer accepted signs the app out.
- **Playing** an upload downloads it once into the cache (`user-sounds/<id>.<ext>`) and plays it natively, so long recordings cost no memory up front. Uploads start at 0:00 when switched on and show their position with a scrubber, Restart and ±15 s. Signing out deletes the downloaded copies.
- **Uploading** picks a file with the system picker, checks it like the website (type, 50 MB, 1 s to 10 min, read by the native player), reserves an upload, sends the file straight to storage with progress (`createUploadTask`), then confirms it.
- Saved volumes of uploads wait for the account's list after launch, as on the web.
